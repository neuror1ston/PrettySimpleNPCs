# Технічна Специфікація та Архітектурний Дизайн: PrettySimpleNPCs

> **Цільова платформа:** Minecraft Java Edition 1.20.1 (Fabric Loader 0.19.5, Fabric API 0.92.2+1.20.1)  
> **Java:** OpenJDK 17  
> **Ключова залежність:** PolyNav Core (`stubname:0.1.0` / `polynav-0.1.0.jar`)  
> **Цільовий сеттинг:** Середньовічний RP / Conquest Reforged  
> **Цільова продуктивність:** 300+ активних NPC при стабільних 20 TPS  

---

## 1. Загальна концепція та філософія інструментарію

Головне правило: **Лоровед, квестмейкер та білдер ніколи не стикаються з сирим JSON, NBT або тривимірними координатами вручну.**  
Весь процес створення, налаштування та режисури персонажів відбувається безпосередньо у грі через інтуїтивний, стилізований візуальний інтерфейс (In-game Admin/Lore GUI).

---

## 2. Ядро сутності (Core NPC Entity) та Оптимізація під 300+ NPC

### 2.1. Екстремальна кастрація ванільної сутності (Lightweight Tick)
Ванільний `PathAwareEntity` / `LivingEntity` містить значну кількість важких перевірок у кожному тіку. У `PrettySimpleNPCs` сутність оптимізується до мінімалістичного кінематичного актора:
1. **Повне відключення Push / Collisions ($O(N^2)$ скасування):**
   - Перевизначено `isPushable() = false`, `collidesWith() = false`, `isCollidable() = false`.
   - Метод виштовхування інших мобів (`tickCramming()` / `pushAwayFrom()`) вимкнено в нуль. Сутності не проводять сканування хітбоксів сусідів.
2. **Ігнорування важких ванільних тіків:**
   - Повний ігнор `isSunBurnTick()`, ванільного `Brain`/Sensor AI та ванільних тригерів навколишнього середовища.
   - Відсутність ванільної фізики тертя та стрибків під час руху по сітці (використовується рушій PolyNav).
3. **Кінематичний рух PolyNav Core:**
   - Повна інтеграція з `ua.stubname.api.INavMeshAgent`, `NavMeshMoveControl` та `NavMeshNavigation`.
   - Плавний перехід через суб-блоки (сходинки, плити, шари Conquest Reforged, $0.125$ воксельна сітка, `stepHeight = 0.6f`).
   - Стрибок виконується виключно при підйомі на повнорозмірний 1.0-блоковий бар'єр.
   - Інтелектуальний рух крізь двері з відкриванням/закриванням без звукового спаму.
4. **Слухач взаємодії (Interaction Listener):**
   - При звичайному ПКМ гравцем без палички налаштування:
     - NPC миттєво зупиняє рух по NavMesh (`navigation.stop()`).
     - Плавно повертає корпус та голову до гравця.
     - Відкриває клієнтський кінематографічний екран розмови.
5. **Стійкість до рейдів, крашів і десинхронізацій (Безсмертя та Авто-респ):**
   - Кожен NPC має паспорт з унікальним ID (наприклад, `cr_tavern_bob`).
   - Якщо NPC загинув через сторонню адмінську команду (`/kill`), падіння у void або десинхронізувався під час вивантаження чанка — диспетчер відновлення (`NpcLifecycleManager`) автоматично респавнить сутність з її збереженим паспортом на вихідному полігоні/координатах PolyNav.
   - **Єдиний спосіб повного видалення:** спеціальна червона кнопка в адмінському GUI з модальним вікном підтвердження («Ви дійсно бажаєте безповоротно видалити персонажа?»).

## 3. Інструментарій творця (Wands & Admin GUI)

### 3.1. Чарівні палички (NPC Wand & Path Wand)
- **Візуальний стаб:** Звичайна палиця з ефектом зачарування (Enchanted Stick glint).
1. **`prettysimplenpcs:npc_wand` (NPC Wand):**
   - **ПКМ по блоку:** створює нового базового NPC на поверхні блока та миттєво відкриває Admin GUI у режимі первинного створення.
   - **Shift + ПКМ по існуючому NPC:** відкриває адмін-панель редагування конкретного NPC (перевірка дозволів: OP / permission level >= 2).
2. **`prettysimplenpcs:path_wand` (Path Wand):**
   - Призначена спеціально для прокладання патрульних маршрутів (`PATROL`).
   - **ПКМ по блоку:** додає нову точку маршруту для обраного в даний момент NPC.
   - Візуалізація лінії та маркерів точок у світі в реальному часі.
   - **Shift + ПКМ у повітря або по блоку:** завершення редагування / очищення вибору.

## 4. Стиль та Структура Admin/Lore GUI

### 4.1. Візуальний стиль (Мінімалізм)
- **Фон:** Глибокий чорний колір (`#000000` / `#0A0A0A`).
- **Рамка:** Акуратна сірувата окантовка (`#4A4A4A` / `#333333`).
- **Вкладки (Tabs):**
  - **Неактивні:** Білий чіткий текст на темному тлі (`#FFFFFF`).
  - **Активна:** Сіруватий акцент/підкладка (`#3A3A3A` / `#555555`).
  - Чіткі поля введення, відсутність надлишкових важких ванільних текстур.

### 4.2. Вкладки налаштування

#### Вкладка 1: Візуал та Ідентичність (Identity)
- **ID сутності:** унікальний ідентифікатор у системі (латиниця, напр. `cr_tavern_bob`).
- **Ім'я та Титул:**
  - Поле імені та титулу (наприклад, `[Корчмар] Богдан`).
  - Візуальні кнопки палітри кольорів, жирності, курсиву.
- **Скін та Модель:**
  - Перемикач моделі: `Default` (Steve / 4px) або `Slim` (Alex / 3px).
  - Формати: класичні `64x64` та `64x32`. (HD 128x128 відкладено).
  - Спосіб підтягування:
    1. За ніком гравця (Mojang Session API / cache).
    2. Локальне завантаження файлу `.png` з ПК клієнта. Передається пакетом на сервер, зберігається у `prettysimplenpcs/skins/<id>.png` та синхронізується з клієнтами.
- **Екіпірування:**
  - Слоти: Шолом, Нагрудник, Штани, Чоботи, Головна рука, Друга рука (drag-and-drop зі свого інвентарю).
- **Повзунок масштабу (Scale Slider):**
  - Діапазон від `0.5x` до `1.5x` (зміна візуального розміру та масштабу хітбоксу).

#### Вкладка 2: Навігація та Поведінка (PolyNav Integration)
- **Базова швидкість:** повзунок/число (дефолт `0.28`).
- **Типи поведінки (AI State):**
  1. `STATIC`: стоїть на місці (опція: погляд на найближчого гравця).
  2. `ROAM_RADIUS`: вільне гуляння найближчими доступними полігонами PolyNav у радіусі $R$ від домашньої точки.
  3. `PATROL`: ланцюжок ключових точок, які задаються за допомогою `Path Wand`. Опції: зациклення маршруту (loop), пінг-понг, пауза (stay ticks) на точках.

#### Вкладка 3: Діалоги та Репліки (Dialogue & Barks)
- **Прив'язка діалогу:**
  - Деревоподібний список файлів із підтримкою папок, підпапок і сортування (`cr/tavern/innkeeper.json`). Кнопка «Створити новий».
- **Фонові репліки (Idle Barks):**
  - Список коротких атмосферних фраз.
  - Налаштування частоти (кулдаун у секундах) та радіусу сприйняття.
  - **Критична вимога:** Репліки **не надсилаються в чат**. Рендеряться виключно над головою NPC плаваючим текстом і лише для гравців поруч.

#### Вкладка 4: Торгівля (Trade Matrix)
- **Економічна модель та конвертація монет:**
  - Співвідношення:
    $$\mathbf{10\text{ мідяків}} = \mathbf{1\text{ срібло}},\quad \mathbf{10\text{ срібла}} = \mathbf{1\text{ золото}}$$
  - Валютний стаб:
    - **Срібло:** шматочки заліза (`iron_nugget`).
    - **Золото:** шматочки золота (`gold_nugget`).
    - Мідяки поки вимкнено / зарезервовано.
  - Можливість динамічного розрахунку та обміну монет.
  - Архітектурно закладено маркер під майбутній бартер (`BARTER_READY`), але інтерфейс фокусується на монетах.
- **Інтерфейс гравця:**
  - У лівому нижньому кутку: відображення грошей гравця (підраховано залізо та золото з інвентарю).
  - Список товарів з ціною та залишками.
- **Адмін-редактор:**
  - Додавання предметів на продаж.
  - Встановлення вартості (залізо/золото).
  - Пули наявності:
    - `INFINITE`: нескінченний.
    - `LIMITED`: лімітований (загальний запас `global_stock`, ліміт на одного гравця `per_player_cap`, таймер скидання `reset_cooldown_seconds`).

## 5. Кінематографічне вікно діалогу (Dialogue Screen) & Actions

### 5.1. UX розмови
1. **Повне блокування:** камера та рух лочаться, темна підкладка.
2. **3D моделі:**
   - Зліва: гравець, голова та корпус повертаються за курсором миші.
   - Справа: NPC, голова та корпус стежать за курсором.
3. **Ефект друкарської машинки (Typewriter):**
   - Посимвольна поява тексту. Клік мишкою пропускає анімацію і показує всю фразу.
4. **Варіанти відповіді:** плавний fade-in після завершення репліки.
5. **Історія діалогу:** скрол вгору колесиком миші для перегляду попередніх реплік.

### 5.2. Система дій (Actions & Placeholders)
У вузлах діалогу підтримуються серйозні механізми тригерів дій:
- **Типи дій:**
  - `console_command`: виконання команди від імені сервера.
  - `player_command`: виконання команди від імені гравця.
  - `give_item` / `take_item`: видача або вилучення предметів.
  - `play_sound`: відтворення звуку гравцю.
  - `set_flag` / `remove_flag`: збереження квестового/сюжетного прапорця у SQLite.
  - `open_trade`: перехід до матриці торгівлі цього NPC.
- **Підтримка плейсхолдерів:**
  - `%player%` — нікнейм гравця.
  - `%player_uuid%` — UUID гравця.
  - `%npc_id%` — унікальний ідентифікатор NPC.
  - `%npc_name%` — відображуване ім'я NPC.
  - `%flag:<key>%` — значення збереженого прапорця зі SQLite.

## 6. Збереження даних

1. **Декларативні конфіги (JSON):**
   - `config/prettysimplenpcs/npcs/<id>.json`
   - `config/prettysimplenpcs/dialogues/**/*.json`
   - `config/prettysimplenpcs/trades/<id>.json`
   - Гаряче перезавантаження: команди `/npc reload dialogues` та `/npc reload all`.
2. **Динамічний стан гравців (SQLite):**
   - Файл: `world/prettysimplenpcs/player_data.db`
   - Таблиці: `player_flags`, `dialogue_progress`, `trade_limits`.
